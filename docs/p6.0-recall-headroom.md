# P6.0 — Recall headroom of the frozen detector on Tier 4 (open scope)

**Date:** 2026-10-12 · **World:** `tier4-v2` (`c8eaafcf…dae96`), `as_of` 2026-06-01 ·
**Scope:** train+tune labels only (P5-7a open analysis); the sealed test split is untouched.
**Script:** `scripts/p6_headroom_probe.py` (works on a scratch copy of the inference store).

This step checks the premise of Phase 6, an LLM as a second recall layer over units the
detector allows ([Coinbase, Part 1 shape](https://www.coinbase.com/blog/part-one-how-coinbase-built-evaluated-and-post-trained-a-fraud-agent)). A recall layer only helps if the frozen
detector misses abusive units on a world it was not tuned on.

## Result

| Unit-level (E-14) at the frozen threshold 0.60 | Value |
|---|---|
| Evaluation units (abusive / legitimate / ambiguous) | 1,309 (202 / 1,051 / 56) |
| Abusive units caught / missed | 142 / **60** → recall **0.70** |
| Legitimate units flagged | **643 of 1,051** (FPR 0.61, precision ≈ 0.18) |
| Abusive source groups (the author's split groups) | 22, of which 4 have missed units; 1 is never caught |
| Missed units per source group | 32, 21, 4, 3 → **two source groups hold 53 of the 60 misses** |
| Detector precision vs base rate | 0.18 vs 0.16; a random pick of the same 785 would catch about 127 abusive units on average, vs 142 |

Misses by family (caught / missed): Direct allocation cycling 44 / **53**, Staged household
56 / 7, Fabricated project team 42 / 0.

Score of the units the detector allows:

| Score band | Missed abusive | Allowed legitimate |
|---|---|---|
| = 0 (nothing fired) | 19 | 108 |
| (0, 0.2) | 11 | 32 |
| [0.2, 0.4) | 10 | 113 |
| [0.4, 0.6) near-miss | 20 | 155 |

Features fired more often on missed abusive units than on allowed legitimate ones:
F-CYC-1 (0.42 vs 0.14). Most other features fire *less* often on the misses (F-DOM-2 0.47
vs 0.73, F-CON-1 0.23 vs 0.46), so the frozen feature set mostly does not separate them.

## Reading

1. **There is recall headroom, but it is concentrated.** 60 missed units exist, but at the
   source-group level this is about 2–4 independent cases, nearly all "Direct allocation
   cycling". (The 60 units span at least 9 detector clusters, but clusters from one source
   group are not independent.) Any recall-layer claim on open scope rests on very few source
   groups. The test split's size and
   composition are unknown until the one-shot sealed read.
2. **Routing is not easy.** The allowed pool is 492 units: 60 abusive, 408 legitimate and
   24 ambiguous. Excluding the ambiguous ones, 468 units, about 13% abusive. The
   near-miss band [0.4, 0.6) is 20 abusive vs 155 legitimate, and 19 misses fired nothing.
   A score-band router sends mostly legitimate units; the LLM would have to separate them
   from the timeline, not from the features.
3. **On this world the detector's bigger problem is precision, not recall.** It flags 61% of
   legitimate units. A recall layer that can only add flags makes this worse. Coinbase's
   agent added recall on top of a deployed first stage. This synthetic detector's own
   baseline already has a high false-positive burden; the two were never compared at a
   common operating point.

## Decision and outcome

Decision: go ahead with an open-scope pilot on Tier 4, then a frozen, pre-registered test on
a fresh repo-blind world. Outcome: Qwen 3.5 9B, prompted and not fine-tuned, flagged
legitimate units more often than abusive ones on this sample (AUC 0.38), and caught fewer
abusive units than a random pick of the same size would on average. See [`p6.1-pilot-results.md`](p6.1-pilot-results.md).
